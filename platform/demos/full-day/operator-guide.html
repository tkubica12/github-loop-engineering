Preparation

Restore the checkout
before preflight.

Approved feeds and locked dependencies belong in preparation, not the room.

Use Node.js 20 or later and Git. From this repository's root, inspect the effective npm registry and confirm that it is approved by your platform owner before restoring the locked development dependencies:

npm config get registry
npm ci --ignore-scripts --no-audit --no-fund
npm ls --depth=0

Keep any approved project-specific feed and the existing package-lock.json. Expect fflate and playwright at the declared versions, with no missing or invalid dependency. Do not rely on packages found in a parent checkout. Restore packages during preparation, not in the room: instructor validation uses this checkout, while attendee labs run in station repositories on GitHub.

If no approved project-specific feed is configured, use the managed feed for this command without changing the user's global configuration:

npm ci --ignore-scripts --no-audit --no-fund --registry=https://packagefeedproxy.microsoft.io/npm/
npm ls --depth=0

If a locked version is unavailable or quarantined, stop and request an approved resolution. Do not edit the lockfile or switch to a public registry to bypass policy.

Workflow-source validation additionally requires the approved gh aw extension at v0.86.2 when you validate workflow sources from the authoring checkout. Browser captures require a separately prepared browser; run npm run validate:html and npm run capture before delivery. Attendees need browser access to their station repository; Git, PowerShell, and gh are optional except where a lab step explicitly asks for them.

Prepare stations.
Protect GitHub evidence.

  • Every attendee needs a reachable repository.
  • Preview features get an honest fallback.
  • Reference artifacts keep the group moving.

  1. Confirm the profile

    Confirm whether the room uses the sandbox or enterprise station profile. Keep organization names, repository prefixes, teams, environments, and preview flags in configuration, not in the learner-facing story.

  2. Verify station repositories

    Open the station roster and verify every repository exists, opens in the browser, has Actions enabled, and contains the prepared pharmacy service, issue forms, workflows, CODEOWNERS, Project link, and lab starter files.

  3. Verify write access

    Before Chapter 1, each attendee must be signed in and able to create a branch in their assigned repository. Pair anyone who cannot write. Do not spend chapter time repairing accounts.

  4. Confirm protection and evidence controls

    Check whether this station's plan and visibility actually enforce default-branch protection and required code-owner review. The sandbox profile creates private personal repositories; do not assume those controls are available without checking settings and a harmless rejection. If unavailable, announce that Lab 3 will record the gap and use a labelled instructor demonstration from a protected repository only when one is available. Confirm Actions and runner capacity separately.

  5. Confirm preview and licensed capabilities

    Record which stations can run GitHub Agentic Workflows public preview, Copilot coding agent, code scanning, Projects, environments, and Secret Protection. Announce any missing capability before the lab and use the documented fallback.

  6. Prepare fallback artifacts

    Keep the five lab guides and their artifacts\ folders open. These reference files let attendees catch up without pretending a generated message verified their work.

  7. Prepare the instructor fallback station

    Keep one separate synthetic station signed in for the opening demonstration. If its plan supports protection, verify a harmless direct-push rejection there in advance; otherwise the Lab 3 enforcement scene is omitted. Label its artifacts as the instructor's work, not an attendee's completed result.

  8. Send the preparation message

    Send each attendee their station repository URL, Project URL, sign-in instructions, expected write role, browser requirement, optional Git and gh setup, and links to the five lab guides. Ask everyone who can to arrive with Copilot CLI or VS Code with Copilot signed in and the station cloned; Lab 2 Step 1 has no time for installation. Attendees without it use the paired fallback.

Seed before the room.
Rehearse the coach.

  • Station creation is a known gap.
  • Dry-run every write first.
  • Probe the coach on one station.

Known gap

Automation creates and pushes one rendered station repository at a time in the sandbox profile. It does not configure branch protection, rulesets, Projects, Copilot policies, or team access. The enterprise profile keeps remote provisioning disabled, so enterprise stations are created and governed by the organization owners. Plan the manual steps below; do not promise a one-command room.

  1. Ten days out · Create station repositories

    For each station in the roster, preview and then create the repository. The sandbox profile refuses --apply for any repository outside its configured owner and prefix.

    node platform/scripts/workshop.mjs plan --profile sandbox --station team01
node platform/scripts/workshop.mjs provision --profile sandbox --station team01
node platform/scripts/workshop.mjs provision --profile sandbox --station team01 --apply

    Expected result: the repository exists, and its default branch contains the pharmacy service, context/intake/, .github/agents/, and .github/instructions/.

  2. Ten days out · Seed the backlog

    Run the seed without --apply first. It reads existing issues and labels and prints CREATE or SKIP for each synthetic backlog item. Apply only after the plan matches your expectation. A second apply is safe: items that already carry their seed marker or exact title are skipped, and nothing is edited or deleted.

    node platform/scripts/workshop.mjs seed --profile sandbox --station team01
node platform/scripts/workshop.mjs seed --profile sandbox --station team01 --apply

    Expected result: five open issues titled [Backlog] … with the backlog and workshop-seed labels. If the plan reports UNVERIFIED, the command could not read the repository, and --apply refuses to run; fix access first. Apply also refuses unless the repository name matches the station and its committed .workshop-station.json marker names the same profile and station.

    Enterprise profile: stations are provisioned by organization owners, but seeding is still allowed because it only adds synthetic issues and labels. Run the same commands with --profile enterprise and a token that can create issues and labels in each station.

  3. Five days out · Configure what automation does not

    Per station: check the repository plan and visibility first, then configure and verify default-branch protection, code-owner review and required CI if available. If unavailable, mark these as not enforced on that station; retain voluntary partner review and the live CI check. Create the Project and link it where supported, grant attendee write access, and confirm Actions. Record capability state for Agentic Workflows, Copilot coding agent, code scanning and Secret Protection.

  4. Five days out · Confirm custom agent visibility

    Clone one station, start Copilot CLI in that folder, and run /agent. Confirm requirement-refiner is listed. Repeat in VS Code with the agent dropdown in Copilot Chat. If an organization policy disables custom agents or Copilot CLI, the coached intake runs as the paired fallback in the Lab 2 guide; announce that before Chapter 2.

  5. One day out · Probe the coach

    Select the coaching agent and ask it to write the requirement for you. It must answer with a question, not a requirement. Then send a CONFIRMED: message and verify it returns a draft that marks anything you did not state as NOT CONFIRMED. Close the chat without creating an issue, so the station stays clean.

  6. One day out · Rehearse the opening in a separate instructor station

    Prepare a different synthetic request so Lab 2's stock-suggestion acceptance criteria remain undisclosed: create an issue titled Prevent overselling after consecutive reservations. Add a test-only PR to test/inventory.test.mjs that reserves five units of MED-001 twice, then requests three more and verifies the reservation result's status is 409 and remaining stock is unchanged. Run the station CI, request a human review, and record the issue, PR, check-run links and SHA. Rehearse opening each tab in ten minutes. Do not use attendee stations for this preparation. If a real chain is unavailable, show this test requirement and the existing synthetic stock tests as local examples, then the labelled archived CodeQL observation separately; do not describe this combination as one live release.

  7. Morning of delivery · Recheck the evidence

    Run the station readiness check below. Confirm the seeded issues are still open and that no attendee-facing issue or pull request exists yet. Keep the Lab 2 feature-request.md open as the facilitator reference; it is not in the station repository, so the coach cannot leak it.

Readiness evidence

Station readiness proves
the live path.

Check repositories, access and preview capabilities before promising the GitHub journey.

Readiness is a live station check: repositories exist, attendees can write, protection capability is recorded honestly, and preview-dependent steps have named fallbacks.

  1. Repository reachability

    Open every station repository URL from the roster. Confirm the repository loads, the default branch exists, Actions are enabled, and the lab starter files are present.

    $stations = @(
  "OWNER/station-team01"
)
foreach ($repo in $stations) {
  gh repo view $repo --json nameWithOwner,url,viewerPermission
}

    Expected visible state: each repository opens in GitHub and reports write or admin permission for the facilitator account. Attendees still verify their own write access at sign-in.

  2. Attendee write access

    Have each attendee create a temporary branch in their station repository, then delete it. The visible state is a branch creation success, not a generated pass message.

  3. Protection evidence

    Check actual default-branch settings and probe evidence for each station, not just the CODEOWNERS file. A private personal sandbox repository may not have enforceable protection on its plan. Record a per-station enforced or not enforced status; skip the Lab 3 push probe where protection is not confirmed. Keep CI check status separate from required-check policy.

  4. Preview capability list

    Record which stations can run Agentic Workflows public preview and Copilot coding agent. If a capability is unavailable, mark the affected step as fallback before attendees start.

  5. Security and delivery capability list

    Confirm whether code scanning, Secret Protection, environments, and deployment records are live in this profile. If not, prepare the recorded first-party evidence and label it as captured evidence.

  6. Guide links

    Open the five lab guides from this operator guide and confirm each local link resolves. The presenter drives attendees through GitHub artifacts, not generated console receipts.

Keep the agenda and its Slides view, Lab 1 through Lab 5, recorded security evidence, and trusted-delivery runbooks open in a dedicated browser profile.

The 13:15 delivery scene combines the CodeQL remediation, Secret Protection, and trusted delivery runbooks. Say which evidence is live and which evidence is recorded. Never claim independent separation of duties, branch enforcement, a live endpoint, or production deployment unless the selected profile proves it that day.

A reachable repo
is not event readiness.

  • Require named human sign-off.
  • Check live evidence for the profile.
  • Reduce scope rather than invent results.

A station repository that opens is only the first gate. Treat readiness as four independent confirmations.

Go evidence

What must be true

  • Every attendee has a station repository URL and can write to it, or is paired with someone who can.
  • Protection and required-review capability are verified or labelled unavailable; Actions and CODEOWNERS are ready, and Lab 3's push probe is disabled where protection is absent.
  • Agentic Workflows public preview, Copilot coding agent, code scanning, Secret Protection, and environment features are either enabled or have an announced fallback.
  • The instructor can open the five lab guides and every referenced lab artifact.
  • A named human signs off that the selected delivery mode is ready.
Not implied

What the readiness check does not prove

  • That preview Agentic Workflows will run without queueing or product change.
  • That every attendee has Copilot coding agent entitlement.
  • That a recorded security or deployment chain belongs to an attendee's current revision.
  • That a green check authorizes release.
  • That sandbox controls equal future enterprise policy.

Go: all live station checks pass, fallback boundaries are announced, and a named human accepts the plan. For recorded delivery, open the retained real release chain and native security records; keep any simulation or historical capture labelled as such. For live scenes, require fresh same-repository evidence.

Warning

Stop or downgrade: repair missing repository access or disabled Actions. If branch protection is absent, skip the attendee push probe and required-review claim; demonstrate it only in a separately verified instructor repository, or record the control as unavailable. Never call a recording live, transfer a check from another revision, or continue without sign-off.

Room execution

GitHub states need
observable outcomes.

Each lab ends at a visible repository artifact, not a generated pass receipt.

Drive the room from the attendee's station repository. Point at the GitHub page that proves progress, state the stop condition, and use the lab artifact when an attendee falls behind.

  1. Prepare · Open the station repository

    Presenter action: Have attendees open their assigned repository, the Lab 1 guide, and the Actions tab.

    Expected visible state: the attendee is signed in, can create a branch and sees .github\workflows\repository-pulse.md; protection status was checked before the room, not inferred from the file.

    Stop or transition: pair anyone without write access before the timer starts.

    Catch-up artifact: use the instructor fallback station only as a labelled fallback.

  2. Chapter 1 · Narrow the agentic workflow

    Presenter action: Point at the workflow contract and ask attendees to remove pull request and Actions read scope, reduce budgets, and narrow the instruction.

    Expected visible state: a draft pull request shows the proposed source change and a Test service check; that check does not compile the agentic workflow.

    Stop or transition: source-only PRs remain drafts. A facilitator may compile, commit and validate the corresponding lock on a station branch before any merge or live run.

    Catch-up artifact: compare repository-pulse.reference.md in the draft PR; do not merge a stale lock.

  3. Chapter 1 · Run or inspect the workflow contract

    Presenter action: Only run Repository pulse if the changed lock is validated and merged and preview is enabled. Otherwise compare the draft source and the old lock; do not suggest that an issue was produced.

    Expected visible state: a live run may no-op if the seven-day window has no new actionable evidence. An eligible signal may produce an owned issue with the <!-- workshop-pulse:v1 --> marker; an unchanged second run should no-op by instruction, though inference may still occur.

    Stop or transition: attendees can explain that per-run caps limit blast radius but do not guarantee recurrence.

    Catch-up artifact: use the reference contract, not a nonexistent recorded run.

  4. Chapter 2 · Refine intent from organizational context

    Presenter action: Have attendees open context\intake\ in their station clone, select the requirement-refiner agent in Copilot CLI or VS Code chat, and answer its questions. Keep the confirmed requirement closed until Step 2.

    Expected visible state: each attendee has a draft produced only after a CONFIRMED: message, with unconfirmed fields marked NOT CONFIRMED. No issue or pull request exists yet.

    Stop or transition: at seven minutes, move everyone to Step 2 whether or not the draft is complete.

    Catch-up artifact: the paired fallback questions in the Lab 2 guide replace the agent; refinement-comparison.md records what the draft missed.

  5. Chapter 2 · Turn intent into GitHub artifacts

    Presenter action: Open the Lab 2 guide, issue form, Project board, and draft pull request.

    Expected visible state: a structured issue exists, the Project card is visible, and the draft pull request is expected-red on test\suggestion.test.mjs.

    Stop or transition: implementation starts only after the red acceptance test proves the current gap.

    Catch-up artifact: use feature-request.md, specification.md, and suggestion.test.mjs.

  6. Chapter 2 · Review and merge the handoff

    Presenter action: Use Copilot coding agent only where entitlement exists; otherwise continue manually and label the fallback in the pull request.

    Expected visible state: the pull request changes only src\inventory.mjs and test\suggestion.test.mjs, required checks are green, review is recorded, and the issue links to the merged PR.

    Stop or transition: the revision is merged or explicitly blocked because checks or scope drift failed.

    Catch-up artifact: copy inventory.reference.mjs if the time box expires.

Warning

GitHub Agentic Workflows are public preview, and Copilot coding agent requires entitlement and repository enablement. Use those capabilities live only when the station proves access. Otherwise use the labelled fallback path in the relevant lab guide.

Turn policy into
visible GitHub control.

  • Owners appear in pull requests.
  • Protected branches reject shortcuts.
  • Security proof stays revision-bound.

  1. Chapter 3 · Add workflow ownership

    Presenter action: Open the Lab 3 guide and .github\CODEOWNERS. Have attendees add the named workflow owner on a branch.

    Expected visible state: the pull request names or requests the workflow reviewer; only an enforced protected station can call that review required.

    Stop or transition: the room can explain who may propose, who may approve, and whether bypass is configured.

    Catch-up artifact: use CODEOWNERS.reference with the real station reviewer substituted.

  2. Chapter 3 · Prove or classify stop authority

    Presenter action: Guide the direct-push probe only for stations whose enforcement was confirmed beforehand. Otherwise skip the push and show a rejection from a separately verified instructor station, labelled as such, if available.

    Expected visible state: an actual rejection on a protected station, or a written gap for stations without protection.

    Stop or transition: record which station produced the proof; never attribute an instructor rejection to an attendee station.

    Catch-up artifact: when unavailable, move to the governance decision record with a missing-control entry.

  3. Chapter 3 · Record seven decisions

    Presenter action: Have attendees copy the governance template to docs\governance-decisions.md, answer seven decisions, and open a pull request.

    Expected visible state: the merged decision record names owners, budget authority, bypass, escalation, and policy scope.

    Stop or transition: vague answers are rejected before merge.

    Catch-up artifact: use governance-decisions.md and fill it with station-specific names.

  4. Chapter 4 · Harden the title workflow

    Presenter action: Open the Lab 4 guide, read the unsafe fragment without executing it, and have attendees create the hardened workflow PR.

    Expected visible state: the hardening pull request is reviewed and merged; PR_TITLE is passed through env and printed with printf '%s\n' "$PR_TITLE".

    Stop or transition: the reviewer can explain why the title is now data.

    Catch-up artifact: compare with title-check.reference.yml.

  5. Chapter 4 · Prove hostile input stays text

    Presenter action: Have attendees open a proof pull request titled Lab 4 proof $(printf SAFE_PAYLOAD).

    Expected visible state: the Pull request title check log prints the literal payload, not command-substitution output.

    Stop or transition: close or merge the proof PR according to the station rule after a partner has seen the log.

    Catch-up artifact: if the check does not run, confirm the hardening PR merged first; then use the instructor station proof.

  6. Chapter 4 · Run CodeQL and state release authority

    Presenter action: Enable the prepared CodeQL workflow if the station profile permits it, then open the Security tab and release-boundary statement.

    Expected visible state: a CodeQL run completes and either shows the seeded finding or a zero-alert result for the station revision.

    Stop or transition: the room states that checks inform release but do not authorize it.

    Catch-up artifact: use recorded CodeQL evidence from the security-remediation guide if code scanning is unavailable, and label it captured evidence.

Capstone

Bind real evidence
before deciding.

  • Pick one revision.
  • Name defects honestly.
  • Record the next decision.

  1. Chapter 5 · Identify the revision

    Presenter action: Open the Lab 5 guide and have attendees find their Lab 2 merged pull request.

    Expected visible state: each table records the pull request number, head SHA, merge SHA, and chosen revision.

    Stop or transition: nobody evaluates a green check until they can name the SHA under review.

    Catch-up artifact: use evidence-checklist.md to structure the search.

  2. Chapter 5 · Bind checks, review and governance

    Presenter action: Point at the PR Checks, Conversation, CODEOWNERS, governance decision record, and Security tab.

    Expected visible state: each relied-on signal names the chosen revision or is recorded as a defect.

    Stop or transition: missing, stale, or wrong-revision evidence blocks or escalates; it is not partial credit.

    Catch-up artifact: the evidence checklist provides the minimum rows.

  3. Chapter 5 · Write the release decision

    Presenter action: Have attendees copy the template to docs\decisions\lab-05-release-decision.md, choose release, block, or escalate, and open a pull request.

    Expected visible state: the decision PR names the revision, relied-on evidence, defects, release owner, and next decision owner.

    Stop or transition: the decision is reviewed and merged, or left open with a named blocker.

    Catch-up artifact: use release-decision.md without inventing evidence.

  4. Chapter 5 · Close the issue loop

    Presenter action: Have attendees open the Lab 1 owned issue if one exists; otherwise create Repository pulse next decision and label it attendee-created, not workflow output.

    Expected visible state: a comment records the capstone decision, evidence or defect to consume next, next action vocabulary, and human owner.

    Stop or transition: a justified no-op, wait, escalate, or retry is visible in GitHub before the adoption discussion starts.

    Catch-up artifact: use the Lab 5 recovery guidance for missing Lab 1 issue or incomplete earlier evidence.

  5. Close · Preserve repository evidence

    Presenter action: Ask attendees to leave pull requests, issues, checks, reviews, and decisions in the station repository unless central cleanup instructions say otherwise.

    Expected visible state: durable GitHub artifacts remain available for debrief and adoption planning.

    Stop or transition: only temporary proof branches may be deleted after their evidence is captured.

    Catch-up artifact: the station repository itself is the evidence store.

Each transition
carries the same story.

A safe output creates a contract; deterministic evidence governs its next boundary.

  1. Briefing to continuous AI

    “We have seen the loop. Now inspect the reasoning automation that keeps it moving.”

  2. Continuous AI to intent

    “A safe output is useful only when it creates a high-quality engineering contract.”

Recovery and cleanup

Fallbacks preserve insight.
Not a false live claim.

Keep each attendee's repository evidence separate from recorded platform examples.

Station access
