Control boundaries

Evidence and identity
constrain the release.

  • Test and package the exact main SHA.
  • Scope Azure identity to one app.
  • Operator intent is not independent approval.

Deterministic gate

The PR adds quantity-contract checks and exposes a safe zero-quantity regression. After correction, the new checks remain a useful change. No agent executes and no security weakness is introduced.

Immutable evidence

CI artifact names and manifests contain the 40-character commit SHA. Release packages are rebuilt and tested from the entered main SHA.

Federated identity

Only the deployment job receives id-token: write. Azure trusts GitHub’s immutable owner ID, repository ID, and exact refs/heads/main subject.

Human boundary

The operator inspects and enters the release SHA. On this private personal repository it is intent, not an independent approval.

Warning

Scope: this deploys a synthetic Node service to a test App Service. It does not claim production readiness, policy enforcement, or a second-person approval.

Only the exact failure
authorizes correction.

Infrastructure failures and historical captures cannot authorize repair, review, merge or release.

Loop role: authorize a bounded correction only when setup succeeded, the failing step ran exactly npm test -- --test-reporter=tap, and the original quantity assertion reports expected HTTP 400 and actual HTTP 201. Infrastructure failure or any other red result is blocked or unclassified evidence. The retained 5 September capture predates this stronger command receipt and remains historical, not repair authorization. A green correction does not authorize review, merge or release.

Preparation

Check access and cost
before provisioning.

  • Require exact repository and resource ownership.
  • Stop if Linux F1 is unavailable.
  • Never broaden deployment identity.

GitHub

Required capability: Create and delete a private repository under the configured owner; push workflows; create variables, pull requests, and workflow runs. A classic gh token needs repo and workflow; cleanup also needs delete_repo. Equivalent fine-grained access is supported.

Stop condition: Do not reuse an existing repository unless it is private and carries the exact workshop-trusted-delivery topic.

Azure

Required capability: Create a resource group, Linux F1 plan, web app, user-assigned identity, federated credential, and scoped role assignment. The operator needs resource creation rights plus Microsoft.Authorization/roleAssignments/write.

Stop condition: Stop if the providers are unregistered, F1 is unavailable in the selected region, or the existing resource-group tag differs.

Deployment identity

Required capability: Website Contributor on the one web app. No client secret is created.

Stop condition: Never broaden the scope to the resource group or subscription to make a failed deployment pass.

Allow 6–12 minutes for setup, 2–5 minutes per Actions transition, up to two minutes for the first F1 health response, and 3–10 minutes for cleanup. Rehearse and warm the service before presenting. Linux F1 has no compute charge where the subscription and region offer it. Bandwidth, logs, policy, quotas, and later SKU changes can still create cost. The scripts never upgrade the SKU.

Prepare without mutation.
Inspect before applying.

Keep one terminal and one run suffix across every isolated resource.

Run every command from the workshop repository root, the folder containing AGENTS.md and package.json. Keep the same PowerShell terminal open so the chosen run settings persist.

Select the approved subscription first. Generate a run suffix once so every command addresses the same isolated resources. If GH_TOKEN shadows the approved cached gh credential, remove it only from this PowerShell process; never print or copy its value.

$env:AZURE_WEBAPP_NAME = "ghw-td-$suffix"

node platform/demos/trusted-delivery/scripts/plan.mjs
node platform/demos/trusted-delivery/scripts/preflight.mjs --live

Go condition: local tests pass; GitHub authenticates as tkubica12 with classic repo and workflow scopes when scopes are exposed; Azure uses subscription tokubica; both providers are registered; Linux F1 and Node 22 are listed in West Europe. GitHub setup must print an immutable subject shaped as repo:OWNER@OWNER_ID/REPO@REPO_ID:ref:refs/heads/main. Preflight changes nothing.

Review the printed names. Git pushes use the same gh credential as preflight, without changing your global Git configuration. Then provision each boundary separately:

node platform/demos/trusted-delivery/scripts/setup.mjs --target github --apply
node platform/demos/trusted-delivery/scripts/verify.mjs --expect red
node platform/demos/trusted-delivery/scripts/setup.mjs --target azure --apply

The first command creates the private repository, green main baseline, and red demonstration pull request. It explicitly enables and reads back immutable OIDC subjects if the repository still has the default name-only setting; an existing custom template is never overwritten. Verification waits up to five minutes for the exact PR head; an older run cannot satisfy it. The Azure command creates only the tagged F1 resources, the main-ref-bound identity, and non-secret repository variables. No GitHub Environment is required in the free private-repository sandbox.

Delivery story

Make each transition
earn its evidence.

  • Correct the bounded regression.
  • Inspect before merge.
  • Reject wrong identity before any OIDC exchange.

  1. 00:00–00:04 · Red pull request

    Do and say: Open the failing zero-boundary test. “The proposal is safe to inspect, but evidence blocks confidence.”

    Evidence: Failed Deterministic CI run tied to the branch SHA.

  2. 00:04–00:08 · Workflow source

    Do and say: Show read-only permissions, pinned actions, timeout, concurrency, and SHA-named artifact.

    Evidence: ci.yml and manifest.json.

  3. 00:08–00:12 · Correction

    Do and say: Run the bounded correction; do not invoke an agent.

    Evidence: Same PR receives one focused commit and turns green.

  4. 00:12–00:16 · Review and merge

    Do and say: Inspect the diff and green run, then merge deliberately. State that a self-operated sandbox does not demonstrate independent approval.

    Evidence: Merge commit on main.

  5. 00:16–00:22 · Release boundary

    Do and say: Show the pre-recorded wrong-SHA rejection: package and deploy were skipped. Read the correct main SHA, then dispatch or open the completed valid run.

    Evidence: A failed gate before any OIDC exchange, then the exact-SHA release artifact and successful deployment.

  6. 00:22–00:25 · Live health

    Do and say: Open /health; connect the response to the release SHA and exact web app scope.

    Evidence: Successful workflow URL and synthetic service response.

Recovery and cleanup

Keep the evidence.
Stop at the failed boundary.

  • No paid-tier escalation or secret fallback.
  • Local verification is not a live deployment.
  • Fresh Actions runs anchor narration.

F1 unavailable

Observed failure: F1 is absent or quota rejects creation. Immediate move: Do not choose a paid tier. Continue through the package job only.

Honest narration: “Azure deployment is unavailable in this subscription; no live deployment occurred.”

Identity failure

Observed failure: OIDC or role propagation fails. Immediate move: Compare the Azure credential with the immutable subject printed by setup; do not use the legacy name-only subject, add a secret, or broaden scope.

Honest narration: “The identity boundary failed closed. The package remains valid evidence, not a deployment.”

Actions queued

Observed failure: Actions is queued. Immediate move: Run local verification and inspect workflow source. Resume when the same run completes.

Honest narration: “This is local deterministic evidence; it is not a GitHub check or Azure deployment record.”

Network unavailable

Observed failure: GitHub or network is unavailable. Immediate move: Run verify.mjs --expect local and stop before release.

Honest narration: “No live evidence has been captured for this run.”

Live path: run the demo against a fresh repository and inspect GitHub Actions directly.

Call the run live only after verify.mjs --expect deployed prints the matching live URL.

Use the current repository's Actions runs as the system of record.

node platform/demos/trusted-delivery/scripts/verify.mjs --expect red
node platform/demos/trusted-delivery/scripts/verify.mjs --expect green
node platform/demos/trusted-delivery/scripts/verify.mjs --expect rejected
node platform/demos/trusted-delivery/scripts/verify.mjs --expect deployed

If any stage is unavailable, state the missing boundary and stop before claiming release evidence.

Reset the demo.
Delete only owned resources.

Cleanup requires the exact workshop ID and preserves other runs.

Reset closes only the demonstration pull request, replaces its named branch, and recreates the red state. It preserves main and Azure.

node platform/demos/trusted-delivery/scripts/reset.mjs
node platform/demos/trusted-delivery/scripts/reset.mjs --apply
node platform/demos/trusted-delivery/scripts/verify.mjs --expect red

Cleanup is destructive, defaults to a plan, and requires the exact workshop ID. It refuses a repository without both the demo topic and run-<workshop-id>, and an Azure group without the matching tag. Other runs' local workspaces are preserved.

node platform/demos/trusted-delivery/scripts/cleanup.mjs
node platform/demos/trusted-delivery/scripts/cleanup.mjs --apply --confirm $env:TRUSTED_DELIVERY_WORKSHOP_ID

# Restore only this process after cleanup.
$env:GH_TOKEN = $priorGhToken

Done: the private repository is absent, the tagged resource group is absent, and the local .state.json and workspace are removed.
