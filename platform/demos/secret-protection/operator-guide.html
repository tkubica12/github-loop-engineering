Recovery

Recover without
lowering the guard.

  • Keep failures visible.
  • Unknown writes are not verified rejections.
  • Never retry automatically or bypass protection.

Missing CLI

Symptom: ENOENT before an API request. Action: Install GitHub CLI and authenticate before the event, then repeat preflight. This is not a server-side rejection.

Access unavailable

Symptom: 401, 403 or unavailable security settings. Action: Stop. Fix account access before the next rehearsal; use the recorded path now.

Missing metadata

Symptom: 409 or 422 without secret metadata. Action: Treat it as an API failure. Do not count a generic conflict as protection.

Sample accepted

Symptom: Inactive sample accepted. Action: Stop and inspect pattern availability. Do not create a commit or exercise a bypass to obtain a more impressive result.

Unknown write

Symptom: Write response lost or timed out. Action: The result is unknown; an unreferenced inactive-sample blob may remain. An unchanged branch does not prove the blob was rejected. Keep the failure record and do not automatically retry.

Existing output

Symptom: Output already exists. Action: Use a new filename; preserve earlier observations.

Reset

Symptom: Need to reset. Action: Run preflight again and use a new output filename. The requests do not change branch history.

Local rehearsal outputs under .workshop/ are git-ignored. Retain the compact redacted result; do not copy raw debug logs into the repository. No Azure resources, branches, commits or repositories need deletion. Clean blobs may remain unreferenced in GitHub object storage; the demo does not promise immediate object deletion. Never remove the shared synthetic repository just to reset this scene.

A native rejection is evidence only when the classification and unchanged branch are verified.
