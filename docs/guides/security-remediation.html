Intent and finding

Export stock.
Not arbitrary files.

  • One synthetic snapshot is the business requirement.
  • Normal tests do not prove filesystem confinement.
  • The unsafe starter stays on loopback.

The pharmacy service offers one downloadable synthetic seed snapshot: /exports/stock.json. The starter instead builds a filesystem path from a caller-supplied name. Its normal export and reservation tests pass, but those tests do not establish that other files are inaccessible.

Warning

Remediation and review

Reduce authority.
Do not clean up strings.

  • Permit exactly stock.json.
  • Read a literal trusted path.
  • Preserve reservation behavior and reviewer-controlled scope.

Open Copilot PR #2. The reviewed change permits exactly stock.json, rejects other decoded names before reading a file, and reads a literal trusted path. It does not try to remove suspicious characters while retaining arbitrary-path access.

  1. Verify the diff changes only the server, its HTTP tests and README.
  2. Inspect the normal export test and the encoded-traversal rejection test.
  3. Confirm that reservations still return 409 without changing stock, and that an explicit successful reservation still decrements it.

The reviewer controls the scope. Copilot does not change workflow permissions, approve its own fix, or deploy it.

Local verification and recovery

Reproduce behavior locally.

  • Observe the harmless starter contrast.
  • Verify rejection and preserved approved behavior.
  • Local checks require no cloud account.

From the workshop repository root, with Node.js 22 or newer:

node teacher/demos/security-remediation/scripts/rehearse.mjs

Expect a harmless manifest read in the starter, then rejection of traversal, double encoding, null bytes, separators and unknown names in the solution. The approved export and reservation tests must still pass.

The script creates two temporary copies, binds ephemeral loopback ports, closes every server and removes only its own copies. Run it again to reset; no GitHub or Azure account is needed.

Verify the continuation separately.

  • The requested regression must detect both mutations.
  • Accepted replay starts no additional worker.
  • Local evidence does not upgrade historical GitHub evidence.

The maintenance issue requests one exact regression: GET /exports/% must return HTTP 400 and exact JSON {"error":"invalid export name"}. Inspect it without changing the historical repository or evidence:

node teacher/demos/security-remediation/scripts/verify-continuation.mjs
node teacher/demos/security-remediation/scripts/verify-continuation.mjs --report <NEW-REPORT.json>

The committed “before” receipt is correctly BLOCKED: the original suite exits successfully, but the required new test is absent. That is missing work, not a task failure and not permission to repair production code.

The trusted verifier builds an owned disposable copy from the original fixture and solution. It runs the full suite with the proposed teacher/demos/security-remediation/continuation/test/export-name.test.mjs, then changes the expected response to a wrong status and a wrong body in separate copies. A passing receipt requires the new regression to catch both mutations. --report accepts only a new path so a previous receipt is never overwritten.
