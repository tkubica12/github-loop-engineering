Before a commit

An API is not an escape hatch.

  • Use only the official inactive sample.
  • Observe the Create a blob decision.
  • No commit or branch change is needed.

GitHub push protection covers supported Git operations, web edits and the REST API. This demonstration uses the Create a blob endpoint: no local commit, branch update, pipeline or deployment is needed to observe its decision.

Warning

Inactive sample only: the script reads a pinned GitHub Skills lesson and removes its documentation marker in memory to restore the token pattern, as the lesson instructs. GitHub labels that sample inactive. It is sent only as file content, never as authentication, and is not saved locally. Never substitute a personal token or customer credential.

The request body illustrates a stock-export client's configuration. It does not add authentication to the workshop service or deploy an integration.

Native evidence

Read the rejection.
Not the assertion.

  • Require native secret-scanning metadata.
  • Match the accepted clean blob.
  • Verify the branch stayed unchanged.

  1. Inspect the repository's enabled secret scanning and push protection settings.
  2. Read the rejected API response. Require a native secret-scanning classification, not merely an HTTP error.
  3. Inspect the clean request: it reads process.env.PHARMACY_STOCK_API_TOKEN rather than embedding a credential. Match the accepted blob's hash and returned bytes.
  4. Compare the default-branch SHA before and after. The branch must remain unchanged.

Response and recovery

Remove the value.
Do not normalize bypass.

  • Revoke or rotate a real exposed credential first.
  • Remove it from every affected commit.
  • Follow the incident process.

For a real exposed credential, revoke or rotate it with its issuer first. Remove it from every affected commit before retrying a blocked Git push; deleting the visible line in a later commit does not remove it from history. Follow your incident process.

This demonstration never bypasses protection. An approved exception workflow is a separate enterprise policy decision, not the normal way to make a red security result green.

Verify the repository control.

  • Personal protection is a different boundary.
  • Private stations need capability and permission checks.
  • Unavailable access means recorded evidence, not weaker controls.

Personal push protection and repository push protection are different controls. This example checks the repository settings explicitly. Public repositories provide the sandbox path; private enterprise stations require the corresponding Secret Protection availability and permissions. Custom patterns and delegated bypass depend on organization configuration.

Stop the live operation. Show the recorded response and explain the unavailable control; do not disable protection, switch credentials or claim a local pattern match is GitHub enforcement.

The recorded operation proves a blocked request, not an alert or bypass audit event. A rejected blob is not a committed leak. The accepted clean blob is an unreferenced Git object; no branch was created or changed.
