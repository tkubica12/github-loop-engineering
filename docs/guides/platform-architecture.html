Control architecture

Give each control a distinct role.

  • Intent and context guide work.
  • Execution proposes; evidence evaluates.
  • Authority governs release; feedback informs recurrence.

Intent

Issue forms and specifications define business value, acceptance criteria, constraints, and risk.

Context

Repository instructions, agent profiles, ADRs, and ownership make team knowledge durable.

Execution

Cloud and local agents work in bounded environments and propose changes on branches. GitHub Copilot is the native path; Claude and Codex are documented hosted partner agents in public preview; harnesses such as OpenCode and Claude Code run on the engineer's machine and are not GitHub-hosted agents.

Evidence

Actions, tests, security products, reviews, and attestations evaluate the proposal.

Authority

Rulesets, CODEOWNERS, environments, and human approval control merge and release.

Feedback

Metrics and agentic workflows identify the next evidence-based action.

Recurrence is not model work.

  • Read stable identity and persisted state.
  • Allow two classroom attempts total.
  • Accepted duplicates and human waits start no worker.

GitHub issues and marked comments are inspectable live carriers. Owned local JSON is the account-free teaching adapter. Both use the same decision semantics; neither makes a cache authoritative. The classroom controller permits two agent attempts total and starts no worker for accepted duplicate input or while a human decision is pending.

Profiles and trust

Shared concepts do not imply shared enforcement.

  • Sandbox keeps account-free local paths.
  • Enterprise policy remains configurable.
  • Every simulation stays visibly labeled.

Rule

Honesty rule: enterprise-only controls are never shown as active in the sandbox. The UI labels each fallback as a demonstration or simulation.

Untrusted input never becomes authority.

  • Treat issue and pull-request text as data.
  • Separate worker and deployment credentials.
  • Protect configuration and make writes explicit.

Untrusted

Issue and PR text supplies input.

Bounded

Agent runtime limits execution.

Proposed

Branch diff records the proposal.

Measured

Checks and scans supply evidence.

Approved

Human decision accepts risk.

Federated

Deployment identity bounds release access.

  • Do not interpolate issue or pull request text into shell scripts.
  • Keep agent credentials separate from deployment credentials.
  • Do not expose protected secrets to untrusted pull request code.
  • Protect instructions, agent profiles, MCP configuration, workflows, and ownership with CODEOWNERS.
  • Make write operations explicit through safe outputs or narrowly scoped token permissions.

Station lifecycle

Plan locally before provisioning.

  • Preflight, render, and verify the sandbox.
  • Remote creation requires explicit application.
  • Sandbox remote deletion remains manual.

npm run preflight
node platform/scripts/workshop.mjs plan --profile sandbox --station team01
node platform/scripts/workshop.mjs render --profile sandbox --station team01
node platform/scripts/workshop.mjs verify --profile sandbox --station team01
node platform/scripts/workshop.mjs cleanup --profile sandbox --station team01 --apply

The default path renders and verifies locally. Remote creation requires an explicit provision --apply. Remote deletion is intentionally not automated in the sandbox profile.

Prove one station before scaling.

  • Configure identity, policies, teams, and isolation.
  • Check effective capability and release trust.
  • Rehearse setup, journey, reset, and cleanup.

  1. Copy platform/profiles/enterprise.example.json to enterprise.json.
  2. Set the organization, visibility, repository prefix, teams, and station isolation model.
  3. Confirm Copilot, partner agent, Agentic Workflow, Actions, Code Security, and Secret Protection policies.
  4. Apply rulesets to protected configuration, default branches, required checks, and code owner review.
  5. Configure GitHub-hosted or ephemeral runners and Actions allow lists.
  6. Configure Azure workload identity federation and environment approval for the deployment demonstration.
  7. Run one clean-room station provision, exact workshop journey, reset, and cleanup before scaling.
