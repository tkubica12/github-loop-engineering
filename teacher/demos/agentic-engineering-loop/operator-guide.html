Story and authority

Preserve one
application lineage.

Never assemble an apparent success from unrelated repositories or commits.

In one hour, follow the synthetic export through a native CodeQL finding, a Copilot proposal, actual human review, historical release evidence and an OpenCode follow-up, then show what a genuine next run must consume. Preserve one application lineage; never assemble an apparent success from unrelated repositories or commits.

Rule

Core message: agents accelerate work; GitHub supplies durable coordination, evidence, policy, and authority across the complete lifecycle.

Do not turn this into a feature catalogue. Every product surface appears only because the pharmacy story needs it.

Enterprise profile

The public sandbox records a human PR review, but this is not enforced separation of duties: it observes the review but does not enforce a code-owner rule. Its environment approval is enforced, but permits the initiator to approve. In the enterprise profile, configure rulesets for required reviews and checks, a distinct deployment-reviewer team, and organization-governed runners and network policies. The same story applies; participant identity provisioning is separate.

Preparation and proof

Choose the delivery mode
before the session.

  • Live needs fresh release and runtime evidence.
  • Recorded uses retained historical captures.
  • Reduced means remediation only.

First complete the instructor checkout and approved-feed preparation. The npm test preflight below requires restored, lockfile-matching development dependencies in this checkout, not packages inherited from an author's machine. Do this before the session.

For recorded mode, inspect the retained records in the following steps rather than recreating their remote actions. A new agent run, review, release or cloud resource requires separate authorization and fresh capability checks.

  1. Select the approved source

    Use the approved public synthetic security demonstration, not private workshop history. A private enterprise repository is an alternative only when native code scanning is available.

  2. Retain the original finding

    Open its actual CodeQL alert and the linked remediation issue. Keep the original finding capture before fixing it.

  3. Prepare the actual proposal

    Prepare the real Copilot PR, its final head, and the positive and negative HTTP tests. Do not fabricate a review comment or agent-authored commit.

  4. Retain the human decisions

    Have a person authorize pending checks and review the final head. Keep the actual review and merge records.

  5. Inspect the historical follow-up

    In recorded mode, inspect the historical OpenCode follow-up against the exact merged application SHA and its actual issue, not just a green job. This source-based maintenance issue predates the recorded deployment. For separately authorized new work, use the current Copilot-primary maintenance path; OpenCode remains optional and experimental, not a preparation prerequisite.

  6. Prepare the live continuation check

    Keep the retained recommendation visible, then run the security-remediation verifier during rehearsal or the closing beat. Read the printed result instead of opening a retained local receipt.

  7. Require release evidence

    Require matching release, artifact and environment-approval evidence before presenting the deployment scene. If those gates are incomplete, stop full-loop delivery or announce a shorter remediation-only demonstration.

  8. Choose live, recorded or reduced

    Decide the delivery mode, because live release evidence expires. The published artifact expires 2026-09-12T19:18:37Z and the tagged Azure app is removed after capture. Choose one:

    Live

    Reprovision the app and dispatch a new reviewed release that a person approves, then update the repository, run id, artifact name and health endpoint together in the collector configuration and in this runbook.

    Recorded

    Announce before the deployment scene that the release and runtime evidence is a historical capture from a completed run, and present the committed release evidence. Never call a recording a live check.

    Reduced

    If no capture is available, deliver the remediation-only path and state that deployment is not evidenced.

  9. Keep fresh proof available

    Keep a live application and an unexpired artifact for the whole session if you selected live mode. The fresh collector stays strict on purpose: a recorded capture is never fresh proof.

  10. Rehearse the selected mode

    Run the local rehearsal in every mode. In live mode, also run the fresh live-chain collector below. Neither substitutes for human sign-off.

  11. Arrange the browser

    Open all links in a dedicated browser profile and arrange tabs in story order.

Live local check

Run the continuation.
Read your result.

  • Original and proposal suites must pass.
  • Wrong-status mutation must fail.
  • Wrong-body mutation must fail.

Run the showcase verifier without a continuation path to confirm the safe default:

node teacher/demos/agentic-engineering-loop/scripts/showcase.mjs --mode rehearsal

It reports NOT_EXECUTED. Then run the live verifier and read the current result:

node teacher\demos\security-remediation\scripts\verify-continuation.mjs

Expect VERIFIED local maintenance verification followed by four passed checks. The command runs the original suite, the suite with the prepared continuation test, and two independent mutation probes in disposable local copies.

This is the closing-beat source of truth. It does not repeat a model invocation, inspect a retained receipt, contact GitHub, approve, merge, deploy, or upgrade the historical maintenance issue.

Do not recreate evidence.
Run fresh or stop.

A future agent attempt needs new authorization, not edited receipts.

The public repository keeps the live verifier and prepared test inputs. It does not keep the recorded receipt or replay machinery that previously revalidated a source-bound local recording.

For a separately announced future agent collection, create new authorization, new work identity, and new evidence. Do not edit retained JSON, recompute hashes, or present a verifier command as proof that an agent consumed prior state.

Accept the live verifier only for what it measures: the original suite, the prepared regression, and the two mutation probes. NOT_EXECUTED never supports a completed-agent claim.

Show the payoff
before minute ten.

Then trace how the bounded fix earned its evidence and human approval.

    Say and do: “The business needs one snapshot. Passing happy-path tests do not prove that only that file is accessible.” Show CodeQL's actual flow.

    Stop condition: Business value and a real security gap are visible.

  2. 00:04-00:09 · Remediation issue, then merged fix

    Say and do: Show the bounded contract and jump to the three-file diff plus resolved alert. Say “the fix exists; now follow how it earned approval”, then return to intent.

    Stop condition: The payoff is visible before minute ten.

  3. 00:09-00:14 · Copilot assignment and context

    Say and do: Open the completed native agent run. Explain attributable delegation, exact context and permissions before generated code.

    Stop condition: Actual agent provenance, not a recreated transcript.

  4. 00:14-00:22 · Narrow proposal

    Say and do: Read acceptance mapping, then the diff. Emphasize small scope, branch isolation and no dependency change.

    Stop condition: Audience can judge the proposal.

  5. 00:22-00:29 · Tests and CodeQL

    Say and do: Contrast application behavior with the original native data-flow alert. These checks answer different questions.

    Stop condition: No security-clearance claim based only on tests.

  6. 00:29-00:35 · Scoped repair

    Say and do: Show caller authority removed and the retained exact verifier feedback. Run the live continuation verifier and read the four check results.

    Stop condition: Local verifier passed; no agent-consumption claim based on source inspection alone.

  7. 00:35-00:42 · Exact-head human review

    Say and do: Distinguish deterministic checks, agent advice and a person's final approval. The sandbox records review but does not enforce code-owner approval.

    Stop condition: The exact PR head was approved before merge.

  8. 00:42-00:48 · Recorded governed release

    Say and do: Show matching package identity, historical environment review and OIDC result. The app is deleted and the artifact expired 12 September 2026; make no fresh live claim.

    Stop condition: The record identifies the reviewed application commit and its approval limits.

  9. 00:48-00:54 · Stateful maintenance decision

    Say and do: Show issue 3 requesting exact GET /exports/% regression behavior, then run the local verifier again if needed. Use the deterministic fixture separately to show owner escalation after the final attempt.

    Stop condition: Issue link alone does not satisfy continuation; verifier output is local proof, not remote execution.

  10. 00:54-00:58 · Operating model

    Say and do: Move to enterprise policy, runners, security products, component budgets, human attention and honest sandbox capability boundaries.

    Stop condition: Audience sees a scalable, stoppable model.

Recovery and close

Switch within ten seconds.
Keep the claim honest.

Missing release evidence means a reduced remediation-only path, not an unrelated simulation.

Agent unfinished

Failure: Agent has not finished. Immediate move: Open the prepared pull request, or the committed remediation record.

What to say: “Asynchronous work is the point; we review the durable proposal, not a spinner.”

Policy unavailable

Failure: Agent policy unavailable. Immediate move: Use prepared assignment evidence.

What to say: “This account path is policy-gated; the enterprise control is part of the story.”

Workflow failure

Failure: Agentic Workflow fails. Immediate move: Show the workflow source and its compiled lock file.

What to say: “This is public preview; the safety contract remains inspectable.”

Checks queued

Failure: Checks are queued. Immediate move: Use completed run in another tab.

What to say: “We never spend audience time waiting for compute.”

Network unavailable

Failure: GitHub or network unavailable. Immediate move: Use the captured security, release and maintenance records under teacher/demos/security-remediation/evidence/.

What to say: “These are recorded results from this same revision, not a live check.”

Release unproved

Failure: Azure evidence missing. Immediate move: Stop the full-loop claim; use an explicitly reduced remediation-only path.

What to say: “This fix reached reviewed main; deployment is not evidenced here.”

Continuation blocked

Failure: The live verifier fails or is unavailable. Immediate move: Show issue 3 as eligible intake and state that the continuation is not evidenced.

What to say: “This proves the need, not a completed continuation.”

Mission control is an optional, separately labeled simulation of an unrelated reservation scenario. It is not a substitute scene for any moment in this story; use it only if you introduce it as a different synthetic example.
